ELK Stack on AWS EC2 — Complete command reference
Below is a consolidated command sheet for your Ubuntu EC2 setup, covering installation, disk expansion, Elasticsearch security, Kibana access, service management, and log collection.

Your installed stack is Elasticsearch 9.5.5, Kibana 9.5.5, and Logstash 9.5.5. Since you've already installed these components and successfully opened Kibana, you can skip the installation steps if you only need the remaining configuration.

1. Install the ELK Stack
Add the official Elastic repository and install the packages:


bash
apt-get update
apt-get install -y curl gnupg ca-certificates

install -d -m 0755 /etc/apt/keyrings

curl -fsSL https://artifacts.elastic.co/GPG-KEY-elasticsearch \
  | gpg --dearmor --yes \
  -o /etc/apt/keyrings/elasticsearch.gpg

chmod 644 /etc/apt/keyrings/elasticsearch.gpg

echo "deb [signed-by=/etc/apt/keyrings/elasticsearch.gpg] https://artifacts.elastic.co/packages/9.x/apt stable main" \
  > /etc/apt/sources.list.d/elastic-9.x.list

apt-get update
apt-get install -y elasticsearch kibana logstash
This adds the repository and installs all three components.

2. Expand the EC2 root disk
Your EBS disk was increased to 20 GB, while the root partition was initially only 7 GB.

Check the layout:


bash
lsblk -f
df -h /
Install the partition utility:


bash
apt-get install -y cloud-guest-utils
For your confirmed partition layout, expand partition 1:


bash
growpart /dev/nvme0n1 1
Then expand the filesystem according to its type:


bash
# Only if the root filesystem is ext4
resize2fs /dev/nvme0n1p1
If the root filesystem is XFS, use this instead:


bash
xfs_growfs /
Verify the result:


bash
lsblk
df -h /
Only run the filesystem command that matches the FSTYPE shown by lsblk -f.

3. Enable and start all services

bash
systemctl daemon-reload

systemctl enable --now elasticsearch
systemctl enable --now kibana
systemctl enable --now logstash
Check their status:


bash
systemctl is-active elasticsearch kibana logstash
Check individual services:


bash
systemctl status elasticsearch --no-pager
systemctl status kibana --no-pager
systemctl status logstash --no-pager
4. Configure and verify Elasticsearch security
If you need to reset the built-in elastic user's password:


bash
Imp =--> /usr/share/elasticsearch/bin/elasticsearch-reset-password -u elastic
Test the Elasticsearch endpoint:


bash
curl -k -u elastic https://localhost:9200
Check the license endpoint:


bash
curl -k -u elastic https://localhost:9200/_license?pretty
Check cluster health:


bash
curl -k -u elastic 'https://localhost:9200/_cluster/health?pretty'
Enter your password when prompted. Avoid putting passwords directly in command history.

5. Configure Kibana for browser access
Edit the configuration:


bash
nano /etc/kibana/kibana.yml
Set:


yaml
server.host: "0.0.0.0"
Save and restart Kibana:


bash
systemctl restart kibana
systemctl status kibana --no-pager
Verify that Kibana listens on port 5601:


bash
ss -lntp | grep ':5601'
Test locally:


bash
curl -I http://localhost:5601
An HTTP/1.1 200 OK response indicates the web server is responding.

In your AWS EC2 security group, allow inbound TCP port 5601 from your own public IP address. Open Kibana using:


text
http://YOUR_EC2_PUBLIC_IP:5601
Replace the placeholder with the actual public IP. For production use, configure HTTPS rather than leaving the browser connection unencrypted.

6. Complete Kibana enrollment
If Kibana asks for an enrollment token during initial setup, generate one on the EC2 server:


bash
/usr/share/elasticsearch/bin/elasticsearch-create-enrollment-token -s kibana
Copy the token into the Kibana browser prompt. It is different from the elastic user's password.

If Kibana is already configured and working, you generally do not need to enroll it again.

7. Configure System integration to collect EC2 logs and metrics
For the recommended approach using Elastic Agent, start in the Kibana UI:

Open Management → Fleet.

Configure a Fleet Server if your self-managed setup does not have one.

In Fleet → Agents, select Add agent and create an agent policy.

Add the System integration to that policy to collect system logs and metrics.

Follow the Linux x64 installation commands generated by Kibana.

You can check whether Elastic Agent is already installed before installing anything:


bash
command -v elastic-agent
systemctl status elastic-agent --no-pager
If installed, inspect its status:


bash
elastic-agent status
elastic-agent version
Important: Install only one Elastic Agent per host. For a one-instance lab, plan the Fleet Server and System integration configuration carefully; don't install a second agent on the same EC2 instance. Fleet enrollment tokens and exact installation commands are generated by Kibana for your configuration.

8. Configure Logstash to ingest test data
If you'd also like to practise Logstash, create a simple pipeline that reads a test message from the terminal and prints the parsed event.

Create a pipeline file:


bash
nano /tmp/elk-test.conf
Add:


ruby
input {
  stdin { }
}

filter {
  mutate {
    add_field => {
      "source_type" => "elk_lab"
    }
  }
}

output {
  stdout {
    codec => rubydebug
  }
}
Run the pipeline:


bash
/usr/share/logstash/bin/logstash -f /tmp/elk-test.conf
Type a test message and press Enter. Logstash should print the event in structured form. Press Ctrl+C to stop it.

This is a local test only; it doesn't send data to Elasticsearch yet. A production pipeline needs an Elasticsearch output with appropriate authentication and TLS configuration.

9. Troubleshooting commands
Use these whenever a service fails or Kibana stops displaying data.


bash
# Recent Elasticsearch logs
journalctl -u elasticsearch -n 100 --no-pager

# Recent Kibana logs
journalctl -u kibana -n 100 --no-pager

# Recent Logstash logs
journalctl -u logstash -n 100 --no-pager

# Disk and memory usage
df -h
free -h

# Listening ports
ss -lntp | grep -E ':5601|:9200|:8220'

# Package versions
/usr/share/elasticsearch/bin/elasticsearch --version
/usr/share/kibana/bin/kibana --version
/usr/share/logstash/bin/logstash --version

# Package installation status
dpkg -l elasticsearch kibana logstash
